The ignore file nobody remembersไฟล์ ignore ที่ไม่ค่อยมีใครรู้จัก

Every git clone has a .git/info/exclude. It works like .gitignore but is never committed, so it is the right place for files that only matter to you.ทุก git clone มีไฟล์ .git/info/exclude ทำงานเหมือน .gitignore แต่ไม่ถูก commit จึงเหมาะกับไฟล์ที่สำคัญแค่กับคุณคนเดียว

Why it existsทำไมถึงสร้างแอปนี้

Your editor settings, a scratch folder, CLAUDE.local.md, a .env with local keys. Adding them to the team's .gitignore is noise in code review, and leaving them out means one careless git add away from a leak. The exclude file solves this, but it is hidden inside .git and easy to forget.ไฟล์ตั้งค่า editor โฟลเดอร์ทดลอง CLAUDE.local.md หรือ .env ที่มี key ส่วนตัว ถ้าใส่ใน .gitignore ของทีมก็รก code review ถ้าไม่ใส่ก็เสี่ยงหลุดเพราะ git add พลาดครั้งเดียว ไฟล์ exclude แก้ปัญหานี้ได้ แต่ซ่อนอยู่ใน .git จนลืมกันง่าย

Git Exclude Manager puts that file in a normal Mac window, for every repository you work on, and keeps the file you already have byte for byte.Git Exclude Manager เปิดไฟล์นี้ในหน้าต่าง Mac ธรรมดา สำหรับทุก repository ที่คุณทำงานอยู่ และเก็บไฟล์เดิมของคุณไว้เหมือนเดิมทุกไบต์

How it worksทำงานอย่างไร

A small helper, registered with macOS as a LaunchAgent, does the reading and writing. The app sends it the new content over XPC. The helper checks the folder is a git repository, keeps the previous file as exclude.bak and writes atomically.helper ตัวเล็กที่ลงทะเบียนกับ macOS เป็น LaunchAgent ทำหน้าที่อ่านและเขียนไฟล์ แอปส่งเนื้อหาใหม่ผ่าน XPC แล้ว helper จะตรวจว่าโฟลเดอร์เป็น git repository เก็บไฟล์เดิมไว้เป็น exclude.bak และเขียนแบบ atomic

Exclude files are yours, so the helper runs as your user and never as root. It only accepts connections from Git Exclude Manager itself.ไฟล์ exclude เป็นของคุณเอง helper จึงรันด้วยสิทธิ์ผู้ใช้ของคุณ ไม่ใช่ root และรับการเชื่อมต่อจาก Git Exclude Manager เท่านั้น
